# Forge Review: Inline Diff Comment Template

This resource defines the standardized schema, rules, and examples for generating inline diff comments and code suggestions during automated PR/MR code reviews on GitHub and GitLab.

---

## 1. Core Principles & Self-Containment Guardrails

All inline comments generated by `forge-review` MUST adhere to strict self-containment:

1. **100% Clean / No Leaked Context**:
   - **NEVER** leak internal agent framework paths (e.g. `.agents/...`, `opencode/...`, `antigravity/...`).
   - **NEVER** leak local workstation filesystem paths (e.g. `/home/...`, `/Users/...`, `C:\...`).
   - **NEVER** expose internal agent roles, session IDs, prompt variables, or orchestrator tokens in review comments.
   - All references to files must use repository-relative paths (e.g. `tutoring/views.py`, `src/components/Header.tsx`).

2. **Actionable & Constructive**:
   - Clearly state the problem, the underlying runtime/security mechanism, and the real-world impact.
   - Always prefer providing a machine-actionable suggestion block (` ```suggestion `) over abstract advice whenever a deterministic fix exists.
   - If suggesting an architectural alternative where direct code replacement is impractical, use clear conceptual guidance without a suggestion block.

3. **Classification Tags**:
   - Every comment must start with a standardized severity/topic badge:
     - `[BUG]`: Logic error, unhandled boundary condition, type mismatch, broken invariant.
     - `[SECURITY]`: Vulnerability, unsafe input, permission bypass, injection risk, secret leak.
     - `[PERFORMANCE]`: N+1 query, inefficient algorithmic complexity, memory leak, unindexed search.
     - `[DATA-INTEGRITY]`: Transaction boundary issue, race condition, data loss risk.
     - `[REGRESSION]`: Broken existing feature or contract incompatibility.
     - `[DRY]`: Unnecessary duplication of logic or constants.
     - `[QUESTION]`: Ambiguous intent requiring author clarification.
     - `[NOTE]`: Non-blocking optimization or stylistic improvement.

## 2. Suggestion Block Syntax

### A. Single-Line Replacement

On GitHub and GitLab, a single-line suggestion replaces the exact line where the comment is positioned.

````markdown
[BUG] Description of the defect and rationale.

```suggestion
<replacement line>
```
````

### B. Multi-Line Replacement

When commenting on a range of lines (using GitHub multi-line comment ranges `start_line` to `line` or GitLab line range positions), the ` ```suggestion ` block replaces the entire selected range.

````markdown
[SECURITY] Detailed vulnerability analysis and remediation explanation.

```suggestion
<replacement line 1>
<replacement line 2>
<replacement line 3>
```
````

## 3. Inline Comment Templates

### Template 1: Code Suggestion (Single / Multi-Line)

````markdown
**{TAG}**: {Concise issue summary}

{Detailed explanation of why the current implementation is flawed, including runtime flow or failure scenario.}

**Impact**: {Specific consequence if left unaddressed, e.g., silent failure, incorrect date filtering, vulnerability.}

```suggestion
{exact replacement code matching indentation}
```
````

### Template 2: Conceptual Note / Question (No Replacement Block)

````markdown
**{TAG}**: {Topic summary}

{Clear explanation of the concern, architectural tradeoff, or missing edge case.}

**Recommendation / Consideration**:
- {Actionable item 1}
- {Actionable item 2}
````

## 4. Real-World Examples

### Example 1: Bug Fix (Off-by-One / Unhandled None Boundary)

**File**: `tutoring/services/slot_calculator.py`  
**Target Range**: Lines 42-45

````markdown
**[BUG]**: Unhandled `None` return from `get_active_term()` causes `AttributeError` when scheduling outside term dates.

When `get_active_term(target_date)` returns `None` (e.g. during school holidays), accessing `term.max_daily_sessions` raises an unhandled `AttributeError` instead of returning an empty slot collection.

**Impact**: Schedule view crashes with HTTP 500 for parents viewing holiday weeks.

```suggestion
    term = get_active_term(target_date)
    if not term:
        return []
    max_slots = term.max_daily_sessions
```
````

---

### Example 2: Timezone Fix (Django Local Date vs Naive UTC)

**File**: `tutoring/views.py`  
**Target Range**: Line 88

````markdown
**[BUG]**: Using `timezone.now().date()` causes off-by-one day calculation errors for users in positive UTC offsets.

`timezone.now().date()` extracts the calendar date from the UTC timestamp rather than the configured project timezone (`settings.TIME_ZONE`). Between midnight and the local UTC offset (e.g., 00:00-10:00 AEST), this resolves to yesterday's date.

**Impact**: Sessions scheduled for today are incorrectly flagged as past sessions during morning hours.

```suggestion
    today = timezone.localdate()
```
````

---

### Example 3: Security Flaw (IDOR / Missing Object-Level Authorization)

**File**: `tutoring/views.py`  
**Target Range**: Lines 134-138

````markdown
**[SECURITY]**: Insecure Direct Object Reference (IDOR) allows any authenticated parent to view other families' invoices.

The invoice lookup retrieves the invoice solely by primary key (`pk=invoice_id`) from the global `Invoice.objects` manager without scoping by `request.user.parent_profile`. An authenticated user can enumerate invoice IDs to access sensitive financial details and student records belonging to other users.

**Impact**: High severity authorization bypass / data exposure.

```suggestion
    invoice = get_object_or_404(
        Invoice.objects.select_related("student", "parent"),
        pk=invoice_id,
        parent=request.user.parent_profile,
    )
```
````

---

### Example 4: Non-Code Architectural Note (Design / Scalability)

**File**: `tutoring/tasks/notifications.py`  
**Target Range**: Lines 60-65

````markdown
**[PERFORMANCE]**: Synchronous email dispatch inside the HTTP request loop blocks the worker process.

`send_booking_confirmation_email(booking)` connects synchronously to the SMTP server inside the view transaction. If the mail gateway encounters latency or network timeout, the client request remains locked, exhausting gunicorn worker capacity under load.

**Recommendation / Consideration**:
- Offload the email delivery task to the Celery / background worker queue (`send_booking_confirmation_email_task.delay(booking.id)`).
- Ensure the booking transaction commits before dispatching the background notification task to prevent race conditions where the worker reads uncommitted state.
````

## 5. Comment Generation Verification Checklist

Before formatting and submitting inline review comments, ensure:
- [ ] Indentation inside ` ```suggestion ` exactly matches the surrounding lines in the source file.
- [ ] The suggestion is syntactically valid and imports all referenced identifiers.
- [ ] No local workstation directories or private agent execution context are present.
- [ ] Line numbers match the new side (`RIGHT` / `new_line`) of the diff hunk.
